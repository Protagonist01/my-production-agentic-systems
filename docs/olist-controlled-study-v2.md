## Why the environment amendment was necessary

Identical source and locked dependencies did not make the candidate portable. The
[`fingerprints` function](../projects/olist-support/src/olist_support/h10_config.py) includes
`platform.system()` and `platform.python_version()` in `environment_sha256`. The original
candidate was frozen on Windows/Python3.13.4. Linux/Python3.12.14 correctly refused it.
Comparison showed that only this field changed for each of the four comparators; source,
prompt, model request, tools, policy and scorer fields matched. Explicit owner approval
preceded the new environment binding. Neither the guard nor source inventory was weakened.

The Linux run host passed four invented checks in603.60seconds: SDK child startup inside
the existing60second test bound; owned workers through SDK fake HTTP,ledger,SQL,state,
receipts and cleanup; stopping after an unsafe semantic effect; and actual process exit37
after a committed SIM action but before a scorer frame. These are readiness/mechanism
observations, not semantic accuracy, production latency or host-loss recovery evidence.

The selected local image uses digest-pinned Python and uv artifacts, locked application
dependencies, two CPUs and1536MiB memory, and a separate owned PostgreSQL service. It does
not mount a Docker control socket. Unrelated Langfuse services were left running. Initial
preparation failures remain: an unavailable derived uv tag; an unselected3.13interpreter on
a3.12base; cross-platform Git index state; and the environment fingerprint refusal. The
corrected setup explicitly selects a CI-supported interpreter, preserves125approved raw
source hashes, and proves the Git tree unchanged after refreshing index normalization.

The Windows targeted entrypoint inspection passed all96batch plans in71.584seconds with
a dedicated bytecode cache. Its separate readiness wrapper failed collection due to a
missing test-module search path; that result establishes neither worker readiness nor a
new model timeout. Prior actual Windows startup failures remain separately inspectable.
The owner selected Linux; no Windows model request occurred in this study.
